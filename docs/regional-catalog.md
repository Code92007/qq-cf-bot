## 使用

- 三视角分别统计口胡通过、代码 AC、二者并集。WA/TLE/CE 只计尝试；历史通过不会被后来失败覆盖。模型静态代码审核不计真实 AC。
- 每题一个紧凑字母徽标。字母颜色表示难度，背景表示当前视角的完成状态，小标记区分「口 / 码」。未知难度为灰色；已发布评级根据真实赛时榜单校准，明确标记为非官方 Rating。
- 草稿按用户和规范题目 ID 自动保存，有本机恢复副本及版本冲突保护。返回墙恢复筛选与滚动位置。
- 绑定 Codeforces/Gym、VJudge、牛客个人 UID，同步公开记录，无需平台密码。绑定仅声明公开账号。后台限量回填，失败保留成功记录；访问墙时距上次成功同步超过 15 分钟自动排队，也可以手动同步/继续回填。没有离线定时任务。
- QOJ 通过下方浏览器插件连接个人 / 团队账号并同步，不需要 CSV / JSON。旧导入数据、批次撤销接口保留兼容。未知映射仍保留原题号，目录补齐后自动匹配。

## 中文题面与依赖

优先取 QOJ 简体中文文本；无单独中文版本时取原始页的单题 PDF，用 `pypdf` 提取文字，再按需复用现有翻译服务。有 Gym 映射时可回退到现有 CF 题面服务。目录完整不等于 954 道中文题面已逐题缓存；首次打开才准备，中文检查失败会明确提示并禁用审核，不会以英文兜底冒充中文。扫描 PDF、图像题意及 PDF 公式排版仍需原始 PDF 核对；保留原题链接。

更新环境需重新 `pip install -e .`（或重建 Docker），新增依赖 `pypdf>=5.0`。口胡审核与难度估算复用 `JUDGE_*`，英文来源翻译复用 `TRANSLATE_*`。未配置模型时，浏览、导入与草稿仍可用；需要翻译的题不会假装就绪。QOJ-only 题当前在原平台交代码，再通过导入或 VJudge 同步记录；站内代码判题仅用于有 CF 映射的题。

真实公网同步/翻译依赖部署环境能访问平台与模型。本次本地环境 QOJ HTTP 抓取受限，已验证失败提示及草稿保留；未将模拟测试等同于全量线上同步或全部中文题面验收。牛客绑定目前读取个人练习历史；2020 昆明已核验牛客原题号，其他未知记录先保留，补齐映射后才能点亮对应题。

## 维护目录

编辑 `src/qq_cf_bot/catalog/regionals.json` 后运行：

```sh
python3 scripts/validate_regional_catalog.py
PYTHONPATH=src python3 -m unittest discover -s tests -p test_regional.py
```

保留已有 canonical ID。新增平台映射前核验赛季、正赛/热身归属、官方题号及题意，不按标题模糊匹配自动合并。补充旧年份时也更新覆盖说明和赛站验收集合。重启服务加载新目录，既有草稿与提交证据无需迁移。目录随 Python 包一起分发，个人数据保存在既有 SQLite 中。

## QOJ 插件同步与草稿

QOJ 改用 `/regional-qoj-sync.user.js` 浏览器插件，参考 oj-submission-wall。登录个人或 ucup-team 团队账号后，在插件连接本站，确认授权，再手动同步。每个账号独立令牌，服务器仅存哈希；重新连接使旧令牌失效，断开授权保留既有记录。仅发送题号、提交编号、判定、提交时间与账号，不发送 Cookie、密码或源代码。团队 AC 合并到代码视角并保留账号来源，不推断团队成员关系。Gym 仍通过绑定 Codeforces handle 同步。页面不再提供手填 CSV / JSON 模板，旧导入记录和撤销入口保留。

每个用户、每道题独立保留一个最新口胡草稿，输入后自动保存；未提交、判错后修改、跨题切换、重新登录均可继续。提交快照独立保留，QOJ 同步与导入不会覆盖草稿。并发编辑发生版本冲突时拒绝覆盖，当前编辑另留本机恢复副本；尚未同步时会明确提示。

插件解析与 oj-submission-wall 1.0.2 对齐：提交者优先识别个人页或提交筛选链接中的账号，纯文本回退会移除单独的 `#` 控件；不同账号链接或账号不匹配会停止，避免把展示内容误认成团队账号。

评级展示：题号色环与分数来自统一发布的离线校准数据。当前 65 场、832 题已按正式队赛时通过数和金银铜牌队通过比例评级；10 场、122 题缺少完整校准依据而保留未评级，页面说明缺失原因。悬浮可查看参考区间及统计依据；单题页提供赛时榜单链接。公开目录和登录后的比赛墙共用发布文件，不再提供单题或整年刷新入口，旧接口返回 403。重建方法与经验分数规则见 [区域赛离线评级校准](regional-rating-calibration.md)。
