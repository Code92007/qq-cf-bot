# ICPC / CCPC 区域赛碎片练习设计

状态：已实现第一版，入口 `/regionals`；实际目录范围、平台能力和运行限制见 [regional-catalog.md](regional-catalog.md)。未落地的团队账号分类、自评补记、题面纠错和更早赛季等条目作为后续规划。目标是在任意多次、每次 1–2 题的练习中，以真实比赛为单位积累进度，随时续写口胡。

## 入口与信息结构

网站新增「区域赛」入口，与单题训练、VP 并列。区域赛不启动五小时倒计时，不要求结束当前比赛后才能看另一场。默认返回上次年份、筛选、比赛和题目。

列表筛选：赛季年份（默认最新有收录题目的年份）、ICPC / CCPC / 全部、区域赛站点、进度视角、未开始 / 进行中 / 全部。年份按赛事官方赛季归档；实际举办日期单独保存，避免延期赛事归错年。总决赛、邀请赛和热身赛单独标记，默认列表只含区域赛正赛。

主入口采用用户指定的 AtCoder Problems table 风格长表墙（https://kenkoooo.com/atcoder/#/table/），每场比赛一行，每道题一个可点击的格子，而非卡片列表。列为「比赛 / 进度 / A / B / C / …」，不同题数的比赛后部留空，不误标为未完成。固定表头和比赛列，移动端允许横向滚动；长列表分页或虚拟化，不要求用户打开比赛才看得到做题情况。单个平台的镜像不得作为另一场比赛重复列出。

登录后直接加载站内用户的已绑定账号、已导入记录与口胡历史，为题格着色；未登录可浏览公开目录，个人进度需登录。首次登录未绑定时在表格顶部提供「绑定平台账号 / QOJ 插件同步」入口。站内登录与 OJ 账号绑定是两个步骤；以后登录自动恢复绑定及进度，无需再次填写 handle。表格先读本地进度，后台同步后增量更新颜色，显示同步时间与历史覆盖状态。

比赛列展示年份、系列、站点和名称，进度列随视角切换。按用户补充的 QOJ 样式使用 25–27px 紧凑字母徽标，题名移到悬浮提示。字母颜色表示难度（未知灰色；模型估算显式标注，不能把 QOJ 点赞当难度），背景表示完成状态，小标记区分口胡和代码。悬浮或键盘聚焦可看口胡结果、AC 平台、最新 verdict 与草稿时间。口胡视角通过题为绿色，草稿为蓝色，需修改为橙色；代码视角真实 AC 为绿色，非 AC 提交为橙色；综合视角任一完成为绿色，以「口」「码」小标记区分贡献，二者都有则同时显示。未开始保持中性底色，中文未就绪附等待标记。颜色必须同时有文字或图标说明，不能只靠色觉区分。

点击题格直接进入该题中文练习页，返回时恢复表格筛选与滚动位置。点击比赛名才打开整场详情。「继续上次口胡」作为表格顶部的快捷入口，不代替长表墙。代码视角把 AC 作为最醒目的状态，但仍保留用户要求的「提交过」记录；可切换「突出 AC / 突出提交过」。

比赛详情保留年份与视角切换，按官方 A、B、C 顺序列题，展示中文标题、口胡状态、代码状态、草稿和中文题面状态。默认不展示算法标签和题解；题目标题正常展示。难度使用字母颜色提示，主动点击可估算，估算不展示解法。用户可按「此视角未完成」「有草稿」「口胡通过但未 AC」过滤，不自动替用户选下一题。

## 三个视角及统计口径

视角是统计与筛选方式，不限制可用的提交功能：

| 视角 | 覆盖条件 | 完成指标 |
| --- | --- | --- |
| 口胡 | 有口胡草稿或口胡提交 | 口胡审核通过 O |
| 代码 | 存在代码提交记录 S，包括 WA、TLE、CE 等 | 真实平台 AC C，另显示尝试数 S |
| 综合 | 口胡活动与代码活动的并集 | O ∪ C，另显示尝试覆盖 O活动 ∪ S |

「纯口胡」表示只看口胡维度，不是排除写过代码的题。同题可以同时有口胡通过和代码 AC。综合完成数按题去重，例如口胡通过 4 题、AC 3 题、重叠 2 题，综合完成 5 题。

避免把「提交过」误写成「做完」：代码卡片文案使用「提交过 5/13 · AC 2/13」；综合使用「完成 6/13 · 尝试过 8/13」。模型源码审核通过单独标为「静态审核通过」，不算真实平台 AC。手动补记的口胡通过带「自评」标识，可单独过滤，与站内审核来源区分。

每题同时呈现两条独立状态：口胡未开始 / 草稿 / 待审核 / 需修改 / 通过；代码未提交 / 评测中 / 未通过（附 verdict）/ AC。已有 AC 不被后续 WA 覆盖，已有口胡通过不因复习失败丢失，另显示最新尝试。

## 中文题面与口胡流程

点击题目直接进入练习页，顶部保留比赛名、题号与题单跳转。桌面左侧中文题面、右侧口胡编辑；手机按「题面 / 做法 / 审核记录」切换。

优先使用经确认的官方中文题面或授权中文来源，其次使用已有中文缓存，再从官方原文生成中文翻译。题意、输入输出、限制、样例说明都必须具备中文版本；数学变量、代码与样例原始数据保持原样。保留来源、原文链接、翻译状态和版本，可反馈翻译错误。

中文尚未就绪时显示「正在准备中文题面」，失败显示重试与原因，不默默返回英文作为可用中文题面。目录仍保留该题并允许保留已有草稿。纯扫描 PDF 和整场题册需先拆题、校验公式与样例，完成前不标记就绪。区域赛使用严格中文模式，不改变现有单题训练的英文兜底策略。

口胡区是一个自由编辑器，可提供「核心思路、正确性、复杂度、关键边界」提示，不强制四个表单。输入后自动保存，显示保存时间；离开前刷新未完成保存，重开恢复。草稿以用户和规范题目 ID 保存，切换比赛或设备可继续；使用版本号避免多标签页覆盖，冲突时保留两份并提示。

提交后复用现有口胡审核及参考题解流程，保留每次做法、审核结论、理由与时间。通过后只提示「口胡通过，可以稍后实现 / 返回题单」，不要求写代码，也不结束整场练习。提示、题解仅在用户主动操作后展示，记录是否使用提示，不提前泄露后续题答案。关闭网页或换题不会自动放弃。

## 账号绑定与历史导入

复用 oj-submission-wall 的适配器思路、题号归一化、分页拉取、重叠窗口增量同步、后台队列和失败保留历史数据机制。不要直接依赖另一个项目 app.py 的运行环境或数据库。

优先接入 Codeforces（含 Gym）、牛客个人账号和 VJudge，随后洛谷。绑定公开 handle / UID，无需用户平台密码；界面显示「声明绑定」而非未经验证的账号所有权认证。团队账号单独标记，团队提交默认不计入个人完成，用户可在专门筛选中查看。

绑定后后台首次回填，显示「排队 / 同步中 / 已同步 / 失败」和已覆盖的时间范围。首次历史未拉完时，不能把缺失记录解释为从未做过。增量同步按账号保存游标，失败不推进成功游标；保留最后成功结果。解绑停止后续同步，是否删除已导入记录作为独立明确操作。

QOJ 参考 oj-submission-wall 最新 1.0.2 插件：登录个人或 ucup-team 团队账号后，通过浏览器连接本站并确认授权，按页同步提交记录。独立账号、独立令牌与来源；支持多个账号合并进度。Gym 直接绑定 Codeforces handle。移除手填 CSV / JSON 的页面流程，保留旧导入接口兼容。

导入分为上传解析 → 预览匹配 → 确认入库：展示可匹配、重复、待确认和无效记录，允许只导入可匹配项。相同提交 ID 幂等，缺少 ID 时用平台、账号、题目、时间、verdict 指纹去重。保留导入批次与证据来源，可撤销某批导入；撤销后按剩余证据重算进度，不能删除独立的站内口胡记录。

历史口胡可通过独立格式补记（题目、做法、通过状态、自评时间），不把历史代码 AC 自动转换成口胡通过。

## 比赛目录与跨平台题目身份

核心难点是题目身份映射。真实比赛拥有一个 canonical contest ID，真实题目拥有一个 canonical problem ID；CF Gym、牛客、VJudge、洛谷题号是它的 aliases。匹配依次使用维护过的映射、镜像指向的原 OJ 和原题号、用户确认。标题相似度只用于建议，不能自动写入已完成状态。

目录按赛季整理，保存比赛官方名称、系列、站点、比赛类型、日期、官方来源、各平台镜像与题单顺序。只发布已确认归属和题单的比赛；目录标明收录范围与更新时间，不宣称覆盖所有区域赛。平台列表与年份关键字可作为候选发现来源，不能仅凭 Gym 名称匹配作为正式目录。

首批应优先覆盖用户想练的近年 ICPC / CCPC 中国区域赛，并逐场核验中文来源和平台映射。具体赛季、站点清单需在实现时核验真实来源，不在设计阶段伪造比赛及题目数据。

## 数据模型与现有工程衔接

新增持久对象：regional_contests、regional_problems、problem_aliases、regional_oral_drafts、regional_oral_attempts、platform_bindings、external_submission_evidence、import_batches、sync_jobs、regional_user_positions。进度从独立口胡通过与代码证据聚合，可以维护可重建的缓存。

现有 webapp.py 的 contest-sessions 面向一次套题练习；新增 regional API 与独立 scope，不把区域赛长期进度寄托于某一轮 session。复用 ChallengeService 的题面、翻译、题解、口胡和代码判定能力；口胡使用 settle=False，区域赛练习不直接改变现有随机训练榜单。代码证据保存真实 verdict 与 provider，不能只存 outcome.accepted，因为当前流程还可能包含 LLM 兜底。

首次打开前准备题面，校验中文就绪后才激活该题。提交请求携带 canonical problem ID、练习上下文与请求幂等键，服务端校验归属和当前上下文，避免多标签切题把结果记在另一题。历史记录及草稿查询始终限制为当前登录用户。已有训练记录仅在能确认用户身份、来源与题目映射时回填，不跨 QQ / Web 用户猜测关联。

建议接口：GET /api/regionals（年份、系列、视角）、GET /api/regionals/:id、GET /api/regional-problems/:id、PUT 草稿（带版本）、POST 口胡提交、POST 代码提交、GET / POST 平台绑定、POST 同步、GET 同步状态、POST 导入预览、POST 导入确认、POST 导入撤销。目录与本地进度查询不等待外部平台同步。

## 实施与验收

第一阶段交付可用闭环：核验过的比赛目录、年份与系列筛选、三视角、本地历史聚合、中文题面、独立口胡草稿和审核、QOJ 插件同步。第二阶段交付自动同步：CF / Gym、牛客、VJudge 的账号绑定、增量回填、跨平台映射与同步状态；后续扩展洛谷和目录维护工具。自动绑定是完整目标的必要部分，不应以只有第一阶段作为全部完成。

验收重点：同一场分三天练习仍正确汇总；两场交替练题互不丢草稿；WA 算提交过但不算 AC；口胡与 AC 重叠只计一次综合完成；同题不同 OJ 镜像共享进度；英文兜底不冒充中文；导入与重复同步不增加计数；未知时间、历史未回填、团队证据准确标注；同步失败不清空进度；静态审核不冒充真实 AC；用户之间的做法与平台记录不可串读。

评级展示：题号前增加评级色环，下方显示具体分数，悬浮提示评级来源；未知评级使用空心灰圈与破折号。登录后可点击「补齐本年评级」后台逐题准备中文题面并估算，仅处理缺失评级，完成后共享缓存；界面显示成功 / 失败数量，失败不编造分数。公开目录也返回已缓存评级。评级任务不修改草稿、提交或完成状态；重启后已完成评级保留，未完成部分可重新发起。
