## 实际统计口径

- 仅显式标记的正式队，排除打星队及未列入队伍表的 jury/system 提交。
- 按题目映射中的 id → label 转换；例如 2025 CCPC 哈尔滨的 A 是 1009，不能用数字下标猜字母。
- 限比赛开始到结束之前的提交，按配置识别秒/毫秒。按最终 verdict 处理重测；同队同题仅首次 AC 计一次。
- 按解题数、罚时、最后一次解题的分钟数恢复正式队终榜；CE 等不罚时的 verdict 按 XCPCIO 规则处理；支持逐题取整与总罚时取整。
- 配置给定金银铜分别枚数时累计成名次边界。`ccpc` 预设使用至少通过一题的正式有效队数，累计 10%/30%/60% 向上取整。相同成绩跨奖牌边界时保留并列名次。
- 记录每题正式通过队数，以及金、银、铜三个互斥获奖队群体的通过数/队数；保存每场各奖牌末队的解题数与罚时。

## 分数与区间规则（经验映射）

这些规则把三人赛统计映射到 CF 风格分数，是人工定义的经验刻度，**没有声称是官方 CF Rating 或经过 CF 选手能力数据拟合**。

统计基准在以下锚点间按 `log(1+通过队数)` 插值，四舍五入到 100 分：全体正式队通过→800；全体与累计铜牌队数的中点→1300；累计铜牌队数→1700；累计银牌队数→2100；金牌队数→2500；四分之一金牌队数→2900；零通过→3300。参考区间默认基准 ±200，限定在 800–3500。

额外硬约束：正式队通过率至少 80% 时上限 1400；铜/银/金牌队内通过率至少 60% 时分别上限 1900/2300/2700；正式队零通过时下限 3100；通过队数不超过 `max(2, 金牌队数×5%)` 时下限 2800。零通过与极少通过的证据较稀疏，分数不应当被看作精确难度。

本次保留既有 50 道题面模型估分作为辅助，其调整为 `clamp((模型分数−统计基准)×0.25, −100, 100)`，取整后仍强制落入统计区间。现有其余 1142 题直接使用统计基准；本次未重新调用模型。每题同时公开统计基准、原模型值（若有）、最终区间与触发的约束，方便后续人工复核。

例：2025 成都 G 正式队 320/320 通过，旧题面估分 2500，新发布分数 900、区间 800–1000；正式队零通过的 F/H 进入 3100–3500 区间。

## 重建与发布

```sh
python3 scripts/build_regional_ratings.py \
  --revision 7d626ddad0b98e8f79ddca7072421cee0a9f00e8 \
  --snapshot data/regional-standings/7d626dd --download \
  --priors src/qq_cf_bot/catalog/regional_ratings.json
PYTHONPATH=src:tests python3 -m unittest test_regional_rating test_regional test_webapp
```

脚本完整校验全部比赛后才写出发布文件 `src/qq_cf_bot/catalog/regional_ratings.json`；冻结/未判完的榜单、无法对应的题号、无奖牌规则或冲突区间会直接失败，不编造统计值。只有目录明确记录 `unavailable_reason` 的比赛允许跳过，发布为 `unrated_contests`；下载失败、文件缺失和校验失败不能自动降级成未评级。每场比赛必须出现在已评级或未评级集合之一。新版本数据随代码部署，公开目录与登录后的墙共用同一发布文件，旧数据库模型值不再参与网站展示。没有网站触发的评级任务；单题与整年旧刷新接口均返回 403 `rating_read_only`。草稿、AC 记录与练习进度不作迁移。
