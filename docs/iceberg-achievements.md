# 冰山成就墙

`/iceberg` 默认保留无需登录的纯享版；`/iceberg?mode=achievements` 使用当前 CF Bot 账号的个人 AC 记录，支持冰山图 / 清单、首次点亮和最近 AC 日期、年份回忆、点亮时间线与文本导出。团队账号默认排除，可单独启用。

## 记录与计算口径

- 合并 CF Bot 代码通过（包括分享题和 VP）、区域赛代码通过、绑定账号导入，以及 OJ Wall 同一用户连接码发布的代码 AC。口胡、WA、活动热力图占位提交不算代码 AC。
- 以原平台题号去重。洛谷 CF、VJudge 原题号、已核验的区域赛镜像统一；没有核验的同名题不猜测合并。同题重做更新最近 AC，题目数量不重复累加。
- 每道题可以关联多个知识点；同一知识点取所有关联题目的最早 / 最近 AC。宽泛标签不扩展成其下的具体算法；精确题目标签与显式的平台映射维护在 `iceberg.py`。
- 洛谷数字标签使用 OJ Wall 已核验的算法字典转换为名称，结合现有公开题目目录与更新缓存补齐标签。年份、地区、来源等非算法标签排除；读取快照不另行爬取外站。
- 平台标签过粗时，通过 `catalog/iceberg-problem-topics.json` 中逐项核验的 OI Wiki / codeforces-go 资料例题补充关联。例如 P5047 的洛谷算法标签只有“分块、莫队”，OI Wiki 的莫队二次离线章节明确以它为例题。目录记录原题号、知识点、资料链接与固定版本行号，详情显示可点击的“资料例题”。只与当前用户实际 AC 的题目求交集，不改提交记录、日期和手动关联。
- 标签同义词显式维护，不直接套用地图的搜索别名；“Tarjan”“平衡树”“树套树”等有歧义的词不推断具体实现。资料中的反例、泛型模板和同一文章里其他算法的例题也不能机械关联。新增资料关联同时用于 CF 复习候选筛选，并沿用难度限制与已 AC 排除。
- 用户可以从自己已有的 AC 题目中补充多个知识点关联，保存在 `iceberg_links`，关联可移除。时间仍然取原始题目 AC，不能用关联操作或同步时间伪造点亮日期。
- 没有原始时间的题目可以留下点亮足迹，但显示“时间未知”，不进入过期复习或年份统计。若关联题目中既有已知日期又有未知日期，说明卡会注明已知日期的局限。年份按 Asia/Shanghai；年份解题量为该年 AC 过的不同题，点亮数量仅统计首次相遇发生在该年的知识点。
- 复习按最近已知 AC 与 30 / 90 / 180 / 365 天间隔筛选。在当前筛选中选择最久未碰的知识点，从本地 CF 题库按标签与难度选出 6 道候选，排除当前记录中的已 AC 题。它是复习线索，不是能力评级。
- 所有个人 API 需要登录，返回 `Cache-Control: no-store`；补充关联需要现有 CSRF 校验。公开地图没有个人数据。

## OJ Wall 发布端

原联动快照仅包含区域赛布尔状态。为保留同一连接码和现有联动，在 OJ Wall 工程根目录安装 `integrations/oj-wall/knowledge_export.py`，并应用 `enable-knowledge.patch`。新增数据只附加在鉴权后的 `/api/integration/v1/me/progress/snapshot`，不会增大 OJ Wall 普通区域赛页面的数据，也不修改原提交记录。

`knowledge` 的版本为 1，包含完整的按原题号与账号类型分组的 `records`；每条含 `key/kind/title/tags/firstAt/lastAt/days`。日期保留每个不同 AC 日，支持中间年份的回忆，不只记录两端。合成活动数据排除，缺失时间保留 null。复用 OJ Wall 的题号归一化、活动识别、用户及活跃账号范围。

CF Bot 原有后台同步每 5 分钟刷新，同步错误保留上一份成功快照，并在成就版标注错误 / 过期；撤销 / 到期连接按原逻辑断开。读取页面不访问外站。升级发布端后，已有连接下次成功同步即可获得历史数据，无需重新生成连接码。
