# I · 事不过三

## 先学什么

需要会扫描字符串的连续相同字符段，以及区分“编码”和“解码”。先把 `001011` 拆成 `00 / 1 / 0 / 11`，记下每段长度。不要急着学信息论；本题的核心是把一个原字符编码成一整段。

## 为什么直接替换字符会出问题

逐字符规定 `0→01、1→10` 虽然可以解码，却需要 2n 个字符，超过 1.5n 的预算。我们需要让更常见的字符花费更少。

设原串 P 中出现次数较多的字符为 b，相同次数时固定选择 0。约定：

- 原字符等于 b，编码段长度为 1。
- 原字符不等于 b，编码段长度为 2。

编码段的字符必须交替，才能让接收者看出段与段的边界。规定第一段的字符恰好等于 P 的第一个字符，之后每段交替使用 0、1。注意：段里写的是 0 还是 1，通常不等于它代表的原字符；**真正承载内容的是段长**。

## 编码例子

令 P=`00100`，0 是多数字符 b。五个原字符对应段长 `1,1,2,1,1`。第一段写 0，随后交替，于是 Q 为：

`0 / 1 / 00 / 1 / 0 = 010010`。

每段最多长 2，因此没有 `000` 或 `111`。Q 长 6，小于等于 floor(3×5/2)=7。

## 少了“多数字符”信息，怎么解码

这是官方一句话中最容易漏掉的细节。接收者能读到 Q 的首字符 f 和第一段长度 d。首字符已经约定等于原串首字符：

- d=1，说明原首字符是多数字符，所以 b=f。
- d=2，说明原首字符是少数字符，所以 b=1−f。

这样不需要额外发送标志位。之后扫描所有段：长度 1 还原成 b，长度 2 还原成 1−b。段数就是原串长度 n。

在上述例子中，首字符为 0，首段长 1，所以 b=0；段长 `1,1,2,1,1` 还原为 `00100`。如果 P=`10000`，第一段长 2、字符为 1，接收者会算出 b=0，同样没有歧义。

## 为什么满足长度限制与唯一还原

设少数字符数量为 t，则 t≤floor(n/2)。n−t 个多数位各用 1 个字符，t 个少数位各用 2 个字符，总长为 n+t≤floor(3n/2)。

相邻编码段使用不同字符，因此扫描出的极长相同字符段恰好就是编码段，不会合并。首段唯一确定 b，所有段长又唯一确定每个原字符，所以整个编码是可逆的。次数相同也没问题：发送端使用约定的选择，接收端仍能从第一段恢复该选择。

## 实现骨架

```text
encode(P):
    b = 0 if count(0) >= count(1) else 1
    current = P[0]
    for ch in P:
        输出 1 个 current（ch==b），否则输出 2 个 current
        current ^= 1

decode(Q):
    提取各段长度 lengths
    b = Q[0] if lengths[0]==1 else 1-Q[0]
    每段长 1 输出 b，长 2 输出 1-b
```

时间、空间都是 O(n)。n=1 时只发送原字符本身，长度为 1，符合限制。

## 通信题特有的注意点

程序会独立运行两次，第二次拿不到第一次的内存，也不能依赖测试数据顺序。不要把 b 存全局数组后幻想第二次还能读取。每组要输出长度、字符串两行并刷新，再读取下一组；阶段由输入的 r 判断。测试时应覆盖“首字符是少数位”“0/1 数量相同”“全相同”“n 为奇数”，并检查 `decode(encode(P)) == P`。
