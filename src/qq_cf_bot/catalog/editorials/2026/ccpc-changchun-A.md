# A · 又一道纸笔问题

## 先学什么

需要会贪心的交换论证、把“次数”当作批量流量统计，以及 64 位整数。不必先学网络流。可以先想一个小问题：左边若干人按高度排队，右边每个人只能接收不高于自己的人，怎样从矮到高尽可能配对？本题相邻两列的匹配就有相同结构。

## 一次操作是一条向右走的路径

操作会在连续若干列各选一个格子，行号可以不变或增加。把格子 (i,j) 的 a[i][j] 看作这么多个待处理的单位。每次操作拿走一条路径上的一个单位。

如果每个单位单独操作，总次数是 S=sum(a)。如果把第 j 列的一个单位和第 j+1 列的一个单位连接起来，它们原本需要两次操作，现在可以合并为一次，恰好少 1 次。

合法连接要求左边行号≤右边行号。因此问题变成：相邻列之间最多能连多少次？最终答案为 S 减去所有连接数。

## 为什么每对相邻列可以独立求

一个单位最多接一条来自左边的线、再接一条去右边的线。这两件事不会互相排斥。某格子有 a 个单位，左边最多接进来 a 条、右边最多接出去 a 条，我们总能在格子内为这些单位配好对应关系。

所有边都从第 j 列指向第 j+1 列，不会形成环，也不会分叉，拼出来恰好是一组合法路径。每接一条边减少一条路径。反过来，任意合法操作都能拆成这种相邻列连接，所以独立最大化每个列边界上的连接数，确实得到全局最优。

## 两列之间的贪心

从上到下扫描右列。处理第 i 行时，左列第 1..i 行的未使用单位都可以接过来，后面的行则不可以。用 `available` 保存已经扫到、还没连接出去的左列单位数：

```text
available = 0
for i = 1..n:
    available += a[i][j]
    joined = min(available, a[i][j+1])
    answer -= joined
    available -= joined
```

为什么当前能连就全连？当前右格比之后的右格限制更紧：之后的右格还可以使用更靠下的左单位。如果一个最优解没给当前右格用某个可用单位，却把它留给了下面，直接把这个连接改到当前右格，不会让总连接数变少。若本来就没有用掉它，连接它只会更好。因此总存在一个遵循该贪心选择的最优解。

## 手算一个两列例子

左列 `[2,0,1]`，右列 `[1,2,0]`。总单位数为 6。

第一行加入 2 个左单位，匹配 1 个，还剩 1；第二行没有新左单位，但可以把剩下的 1 个匹配给右列第二行；第三行加入 1 个，但右格为 0，无法再匹配。共连接 2 次，最少操作为 4。

剩下的左列第三行不能接到右列第二行，因为那会向上走，违反行号不减。

## 完整算法、复杂度和边界

先求 S，再对每个 j=1..m−1 独立运行上述扫描。时间 O(nm)，存整个矩阵时空间 O(nm)。a[i][j] 最大为 10^9，单位数量不能展开成循环；`available`、S、答案都要用 64 位整数。

- 每切换一对相邻列，要把 available 归零。
- m=1 时无法连接，答案就是这一列的和。
- n=1 时只能在相邻位置连接，公式会退化为 S−sum(min(a[j],a[j+1]))。
- 只有值为 0 的格子时答案为 0；路径不允许跳过一个没有单位的中间列。

## 学懂后的自测

用一张 2×3 的小矩阵，先画出每个单位的连接，再把连接追踪成完整操作。重点验证同一个中间格子既接进来又接出去是允许的；这一步理解后，“相邻列独立”才不再只是一个结论。
