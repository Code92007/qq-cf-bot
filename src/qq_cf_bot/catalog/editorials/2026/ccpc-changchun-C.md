# C · 无忧旋律

## 先学什么

需要会：数组计数、取模、循环下标。暂时不需要字符串匹配算法。先练习把 `1,2,3` 重复成 `1,2,3,1,2,3,…`，再回答“第一个数换成 2 后，第 8 个数是多少”。能写出这个计算式，就可以继续。

## 把题意压缩成一个选择

原曲不是任意排列。它只能是 `1,2,…,k` 的某个循环位移不断重复。第一项一旦选定，后面的每一项都确定了。我们只需要在 k 个起点中，找出与输入相同位置最多的那个；其余位置各修改一次。

直接枚举起点，再检查 n 个位置，需要 O(nk)，数据最大时不行。官方题解的关键是反过来问：**当前位置如果不修改，它支持哪个起点？**

## 从单个位置反推起点

以下统一使用从 0 开始的数组下标。设起点的编号是 s，取值为 `0..k-1`，它代表原曲第一项是 `s+1`。那么位置 i 的原曲数值是：

`expected[i] = (s + i) % k + 1`。

若输入值 v 在 `1..k` 内，希望当前位置保留下来，就必须有：

`s = ((v - 1 - i) % k + k) % k`。

这个 s 是唯一的。所以每个合法值给一个起点投一票。若 v 大于 k，它不可能出现在任何原曲里，不能给任何起点投票。

例如 `n=5, k=3, b'=[1,2,3,1,3]`：前四个位置都支持 s=0；最后一个位置支持 s=1。票数是 `[4,1,0]`，最多保留 4 项，答案是 1。

## 算法与正确性

```text
cnt[0..k-1] = 0
for i = 0..n-1:
    if 1 <= b[i] <= k:
        s = ((b[i] - 1 - i) % k + k) % k
        cnt[s] += 1
answer = n - max(cnt)
```

固定 s 时，每一张票恰好对应一个无需修改的位置，既不多算也不漏算。因此 `cnt[s]` 就是该方案最多能保留的位置数。枚举所有起点的最大票数，也就覆盖了所有可能的原曲。所有不匹配的位置都能单独改成目标值，所以下界可以达到。

## 复杂度与容易写错的地方

时间 O(n+k)，额外空间 O(k)。因为 k≤n，也可以写作 O(n)。

- C++ 的负数取余可能为负，要把余数归一化；Python 的正模数取余已经非负。
- 不要把大于 k 的值先取模再投票；例如 k=3 时，输入 4 必须修改，不能当成 1。
- 0 下标公式中的 `v-1-i` 与官方 1 下标写法不同，不要混用。
- 多组数据要清空计数；不是只检查前 k 个音符。

## 学懂后的自测

当 k=2、输入有五个 1 时，两个起点分别能保留 3、2 项，因此答案为 2。若所有输入都大于 k，答案就是 n。能独立解释这两个边界，再不看公式写出投票过程，才算掌握了“枚举方案 → 让元素投票”的转化。
