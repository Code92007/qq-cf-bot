# K · Sequence Operation（序列操作）

## 题意与规模

一次操作选择位置 i，把 a[i] 变为其前面所有数的 mex；mex 是没有出现的最小非负整数，空集的 mex 为 0。首先最大化最后一项，再在达到最大值的方案中最少操作。n 的总和不超过 10^6，a[i] 可以达到 10^9。

## 先学什么

先学 mex、布尔计数数组和从左到右的贪心。可以先手算 `[6,5,4,3,2,1]`：修改第一个数得到 0，再修改第二个数得到 1；第三、四、五项的 4、3、2 已经可以保留，最后一项再改成 5。一共三次，而不是把每个数都改成下标减一。

## 最大值只可能是两者中的较大值

最后一项若被修改，它的新值是 n−1 个数的 mex，不可能超过 n−1。若不修改，它保持 a[n]。另一方面，依次把前面的第 i 项改成 i−1，再操作末项，确实能够得到 n−1。

所以最大值是 `max(a[n],n−1)`。如果 `a[n]>=n−1`，保持原样已经最优，操作次数为 0。以下只讨论 `a[n]<n−1`。

要让末项等于 n−1，前 n−1 项必须恰好包含 0 到 n−2 各一次。最后修改末项还要花一次操作，因此任务变成怎样最快修好前缀。

## 扫描时尽量保留已经有用的值

从左到右处理前 n−1 个位置，维护已经处理的数的集合 S，以及它的 mex m：

- 如果当前值在 `[0,n−2]` 中，且此前没有出现，就保留。
- 否则当前位置必须修理：对它操作一次，变成 m。
- 将处理后的值加入 S，推进 m，直到 m 不在 S 中。

这次操作在原题中可以真实执行，因为此前的前缀已经固定，其 mex 正是 m。扫描结束时，S 含有 n−1 个互不相同、且处于 `[0,n−2]` 的数，所以它正是目标集合。答案为扫描中修理的次数加一。

注意不能简单输出“缺失数字的个数”。比如前三项 `[5,0,1]` 要变成 0、1、2 的排列，原来只缺 2，但第一个位置只能被改成 0；这会迫使后面的 0 再改成 1，继而迫使后面的 1 改成 2。

## 为什么一次操作最多帮我们省一次修理

把上述扫描需要的修理次数记作势能 F。目标排列的 F=0，算法本身用 F 次操作就能修好。只需说明任意一次原题操作都不可能让 F 降低超过 1。

比较操作前后两次贪心扫描。位置 i 之前完全一样；操作把当前位置换成此前原序列的 mex。如果前面有尚未修好的值，可以先把“扫描前缀”和“原前缀”的区别逐个消去来看：贪心修理总是补当前最小缺口，已补的缺口只能把 mex 向右推，而不会删除一个已存在的小值。

在 i 处，扫描使用的集合要么相同，要么只相差“保留的原数”和“新补的缺口”这两个值。继续扫描时，除遇到这两个差异值外，两条扫描的判断一致。遇到差异值会交换这个差异，或者让两集合合并；一次少修理之后，另一条扫描也补上相应缺口，不能再次无代价少修理。故修理次数的净减少至多为 1。

这也是“保留当前合法首次出现值”的交换思想：提前丢掉它至多把一次修理移到别处，无法凭一次操作消去两次必需修理。因此任意方案至少要 F 次修改前缀；最后一项还至少要改一次，贪心达到下界。

## 可直接实现的伪代码

```text
if a[n] >= n-1:
    output a[n], 0
else:
    seen[0..n-2] = false
    mex = 0
    changes = 1                  // 最后修改末项
    for i = 1..n-1:
        x = a[i]
        if x > n-2 or seen[x]:
            x = mex
            changes += 1
        seen[x] = true
        while mex < n-1 and seen[mex]:
            mex += 1
    output n-1, changes
```

每个位置访问一次，mex 总共只增加 n−1 次，时间 O(n)，空间 O(n)。越界值必须先判断，不能拿可能为 10^9 的 a[i] 直接访问 seen。

## 边界与验证

n=1 时最大值就是 a[1]，无需操作，因为所有数非负。原末项已经等于 n−1 时也应输出 0 次。本工程对小数组建立真实的操作状态图，用 BFS 求最少步数，再与上述答案比较；报告记录实际运行规模。没有提交在线评测。
