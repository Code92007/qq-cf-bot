# J · Re: Becoming the Programming Champion

## 先学什么

先学单机调度、完成时刻之和与交换论证，然后学最大堆。这里不是三个人并行做题：只有一台电脑，所有题串行，每题必须在指定队员离开之前完成。

## 题意

有 n≤10^5 道题，每题指定由三个队员之一完成，用时 c≤300。队员有离场截止时刻 l[1..3]，只有一台电脑。所有题必须完成，且题的完成时刻≤其队员的截止时刻；求能否使完成时刻之和严格小于冠军罚时 t。

任何可行方案中的空闲都可以删掉，使全部完成时刻更早、罚时更小。因此只考虑从时间0连续做题，总结束时刻 T=sum(c)。

## 倒着选择最后一题

一题若被排在当前末尾，它会在 T 完成，因此必须满足 deadline≥T。在所有满足条件且尚未安排的题中，选用时 c 最大的那一道，把它放在末尾，罚时加 T，然后 T-=c。

若没有任何候选题，就不存在可行排列：无论如何排，总有一题必须在当前 T 完成，而它们全部赶不上截止时间。

## 交换证明为什么是“最长放最后”

取一个最优可行排列，设贪心想选的最长候选题为 X，实际末尾是 Y。X 的截止时间≥T，可以安全移到最后。把 X 与 Y 交换：

- Y 提前完成，当然不违反它的截止时间。
- 两者之间的题全部提前 c[X]-c[Y]≥0，也不会违反截止时间。
- X 最后在 T 完成，仍满足自己的截止时间。

若它们之间有 q 道题，罚时总变化为 -(q+1)*(c[X]-c[Y])≤0，所以不会变差。于是存在一个以贪心选择结尾的最优方案，删除最后一题后归纳即可。

## 堆实现

将全部题按 deadline 从大到小排序。随着 T 减小，把 deadline≥T 的题加入最大堆，堆按用时排序。每题只入堆、出堆一次。

```text
T=sum(c); penalty=0
重复 n 次：
    将所有尚未入堆且 deadline>=T 的题入堆
    若堆空：不可行
    c=弹出最大用时
    penalty+=T
    T-=c
若可行且 penalty<冠军罚时：YES，否则 NO
```

三个队员同一个截止时间也没关系；同用时任取。比较必须是严格小于，罚时相等不能夺冠。开始时刻严格早于离场由 c>0 和完成≤截止自然保证。

## 例子

两道题用时2、5，截止分别2、10。总 T=7，只有5分钟题能放最后，罚时先加7；剩 T=2，放2分钟题，再加2，总罚时9。正向顺序为2分钟题、5分钟题。

如果两题截止都为6，T=7时堆空，说明总有最后一题超时，并非只要各题单独能在截止前做完就够。

## 复杂度与校验

排序和堆合计 O(n log n)，空间 O(n)。总时长可到3×10^7，罚时可到约3×10^12，必须使用64位整数。工程枚举小规模全部题目排列，严格检查截止与最小罚时，对比反向贪心。尚未在线提交。
