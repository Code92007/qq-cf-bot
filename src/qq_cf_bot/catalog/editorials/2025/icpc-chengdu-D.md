# D · Deductive Snooker Scoring

## 先学什么

学习有限状态建图、BFS 和前驱恢复路径。重点是把“下一步允许做什么”所需信息都放进状态，而不是套真正斯诺克的规则；本题规则以正式题面为准。

## 状态为什么要有五项

题面给出 A、B 分数，各不超过 200；剩球数 n 在 0 到21；当前球员 p 为0或1。初始21个球，A先击球。除这四项外还需一位 phase：刚进红球后，下一杆可以任选彩球，即使这已经是最后一个红球。

状态写成 `(a,b,n,p,phase)`，phase=1 表示等待这一杆彩球。若忽略它，n=6 时无法区分“刚进最后红球，还能任选彩球并放回”与“开始按2到7清彩”。

## 完整转移

只对 n>0 的状态产生后继，比赛结束后不能再击球。

- 任意失败：输出 `/`，球员变成 `1-p`，phase=0，分数球数不变。
- phase=0 且 n>6：进红球，输出 `1`，当前球员加1，n减1，phase=1。
- phase=1：任选 c=2..7，输出数字c，当前球员加c，n不变，phase=0。彩球需要放回。
- phase=0 且 1<=n<=6：输出 `8-n`，给当前球员加该分数，n减1，phase保持0。

从 `(0,0,21,0,0)` 开始 BFS。注意官方讲义起点的球员编号存在笔误，正式题面明确 p=0 是 A，且 A 先手，故应从0开始。

## 一次搜索回答所有询问

所有测试共享同一张状态图。第一次到达一个状态时保存前驱与使用的字符。询问 `(A,B,N,P)`，检查 phase=0 和1两个状态；任一可达就沿前驱回溯并反转字符串，否则输出 `NA`。初始状态的正确路径可以为空字符串，应输出一个空行；也可以输出 `//` 表示两次失败后仍回到初态。

最大总分为 `15*(1+7)+(2+3+4+5+6+7)=147`，所以 a+b>147 的状态没有必要存。数组编码比哈希表更稳定；上界可用148×148×22×2×2，实际只有其中一部分可达。

## 为什么不会超出100个字符

BFS找最短击球串。成功击球至多36次：15次红球、15次放回的彩球、6次清彩。两个成功击球之间，phase=0时失败至多一次；phase=1时至多两次，因为两次失败可以清除phase并保持球员，再多两次完全重复状态。phase=1的间隔至多15个，所以任何可达状态都可压成至多 `36+37+15=88` 步，满足100的限制。

## 例子与正确性

`1` 后状态是 `(1,0,20,0,1)`；再输出 `7` 得 `(8,0,20,0,0)`，球数仍20。再 `/` 才换成 B。这个例子同时检查加分、放回球和轮次切换。

每一条边都恰好对应题面的一种合法击球，题面的每种击球也都列成了边，因此可达性与可恢复历史等价。BFS与前驱恢复给出合法且足够短的历史。预处理 O(S) 时间与空间（每状态至多7个后继），每个询问 O(输出长度)。不要在 n=0 后加入失败边，否则会把样例中的 `(147,0,0,1)` 错判为可达。
