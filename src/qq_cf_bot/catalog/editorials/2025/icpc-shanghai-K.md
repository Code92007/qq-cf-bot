# K · No more regrets

## 先学什么

建议依次学平方分块、区间加/赋值懒标记、前缀最小值与最大值、二分查找。官方还给了 O(log³n) 的线段树做法，这里先把更容易实现和核对的 O(√n log n) 分块做法讲完整。先能手算某段的“每个前缀最小值×最大值之和”，再处理跨块影响。

## 一个整块需要保存什么

对块内从左到右的每个位置 i，预处理

`p[i]=min(a[块首..i])`，`q[i]=max(a[块首..i])`。

p 单调不增，q 单调不减。再保存三个前缀和：sum(p)、sum(q)、sum(p*q)。若询问进入这个块之前，已经见过的最小值为 u、最大值为 v，则块的贡献是

`sum_i min(u,p[i])*max(v,q[i])`。

不能只保存块最小值、最大值和元素和；它们无法描述不同位置的前缀贡献。

## 两个分界点，把求和分成最多三段

令 A 为满足 p[i]≥u 的前缀长度，B 为满足 q[i]≤v 的前缀长度。由单调性，各做一次二分即可找到。

- 前 min(A,B) 项，两侧都被外部值截住，贡献每项 u*v。
- 若 A&lt;B，中间 A+1..B 项的贡献是 p[i]*v，用 sum(p)。
- 若 B&lt;A，中间 B+1..A 项的贡献是 u*q[i]，用 sum(q)。
- 最后 max(A,B)+1..块尾的贡献是 p[i]*q[i]，用 sum(p*q)。

例如块内 a=[3,1,4]，进入时 u=2、v=5，则 p=[3,1,1]、q=[3,3,4]，A=1、B=3，贡献为 `2*5+1*5+1*5=20`。

处理完块后更新 `u=min(u,块最小值)`、`v=max(v,块最大值)`。按从左到右顺序扫查询中的块，不能随意打乱顺序。

## 整块加法不必重建

若整个块都加 d，前缀最小值、最大值都同步加 d。可以只存 add 标记，二分时把阈值 u、v 减去 add，在原 p、q 上查找。

实际的前缀和转换为：

```text
sum(p+d) = sum(p)+len*d
sum(q+d) = sum(q)+len*d
sum((p+d)*(q+d))
  = sum(p*q)+d*(sum(p)+sum(q))+len*d*d
```

这样整块加 O(1)，查询整块仍为 O(log B)，其中 B 为块长。若维护的就是当前真实前缀和，也可以按上述公式立即更新总量，并保留用于二分的基准数组和偏移。

## 整块赋值与散块

整块赋成 x 后，所有 p、q 都为 x，贡献直接为 `len*min(u,x)*max(v,x)`，不必维护无意义的二分数组。新赋值覆盖旧赋值和加法；后续整块加可以直接改变赋值值。

遇到部分覆盖的块，先把懒标记下放到所有实际元素，逐个修改，再 O(B) 重建 p、q 和三个前缀和。询问两端的散块也逐元素更新 u、v 并累加。

## 正确性、复杂度与整数规则

进入块前的全部信息只通过 u、v 影响块内各前缀；两个单调分界完整列出 min/max 四种组合。因此每块计算精确，顺序拼接得到整个区间答案。

每次修改 O(B+n/B)，查询 O(B+(n/B)log B)，取 B≈√n；空间 O(n)。题目要求模 2^64，C++ 中累加、乘法用 `uint64_t` 的自然回绕。数组元素与 add 标记的比较、二分阈值仍使用足够宽的有符号整数，因为 d 可以为负；不能把负标记转成巨大无符号数参与大小比较。

小数组随机混合加法、赋值与询问，逐元素扫描作为对拍，尤其覆盖“赋值后加、加后赋值、负加法、只覆盖一个元素、询问恰好落在块边界”。
