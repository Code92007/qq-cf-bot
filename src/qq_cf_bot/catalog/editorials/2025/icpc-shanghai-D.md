# D · Not a subset sum

## 先学什么

需要二进制下标、分治、递归复杂度。先从 n=2 手算全部九种 `0/1/?` 模式，分清“模式里有问号”与“数值位上做异或”两件事：每个模式内部求普通整数和，最后才把不同模式的和异或起来。

## 直接枚举为什么慢

共有 3^n 个模式。如果每个模式再扫描 2^n 个下标，就需要 6^n 级别的工作。即使只枚举符合模式的下标，总访问量也会达到 4^n：每个下标的每一位都可以选固定值或问号。

关键是把相同的子问题结果复用。拿某一二进制位，把原数组拆成该位为 0 和为 1 的两份，分别递归求出其余 n-1 位所有模式的和，记为 L、R。两边的模式顺序必须完全一样。

## 三种情况只需要两次递归

对于剩余位的同一个模式 t：

- 当前位填 0：结果是 L[t]。
- 当前位填 1：结果是 R[t]。
- 当前位填 ?：两个集合不相交，结果是 L[t]+R[t]。

因此返回数组就是三段 `L`、`R`、`L+R`。这里 L+R 表示逐项相加，不是拼接。只有一项输入时，递归返回只含这一个数的数组。

例如 n=1、a=[3,5]，三个答案是 3、5、8，最终 `3 xor 5 xor 8=14`。n=2 时先对每一半得到三个和，再生成九个和，不必重新扫描四个输入。

## 选高位分治可避免复制下标

题面规定字符串第一位对应最低位，但只要求所有答案的异或和，不要求按模式顺序输出，所以完全可以从最高二进制位递归。这样 a 的前半段对应高位 0，后半段对应高位 1；两次递归天然处理连续数组。

```text
solve(a, n):
    若 n==0：返回 [a[0]]
    L = solve(a 的前半段, n-1)
    R = solve(a 的后半段, n-1)
    返回 L，R，以及逐项相加得到的第三段
```

最后一层不一定要真正返回长度 3^n 的数组，可以在合并时直接把 L[t]、R[t]、L[t]+R[t] 异或进答案，从而降低峰值内存。

## 正确性与复杂度

归纳假设 L、R 已经正确覆盖所有剩余位模式。当前位有且仅有三种选择，并且问号对应两个互不相交的下标集合的并，因此合并不重不漏，所有模式的和均正确。

时间递推是 `T(n)=2T(n-1)+O(3^(n-1))`，解为 O(3^n)，不是 O(n·3^n)。空间可做到 O(3^n)，顶层只累积异或时约需两个长度 3^(n-1) 的中间数组。n=16 时 3^n=43046721，直接用 64 位保存整张结果会非常占内存。

由于 a[i]≤9、项数≤65536，单个和至多 589824，32 位整数足够。不能为了省空间在递归子问题里提前把数组压成“一个异或和”：一般无法从 xor(L) 和 xor(R) 恢复 xor(L[t]+R[t])，因为普通加法带进位。

## 自测

n≤5 时枚举所有三进制模式，再枚举原数组下标逐一检查位约束，与分治结果逐项或按多重集合比较。全零数组的结果应为 0；只有一个非零值时，每个包含该下标的模式都产生同一个和，这是检查问号分支的好例子。
