# H · str(list(s))

## 题意与规模

题目按形式化规则把每个字符替换成 5 个字符，共进行 k 次。最终对每个下标模 p 的余数，求相应位置的 ASCII 码之和，模 10^9+7。初始长度≤10^5，k,p≤3000。字符串长度每轮乘 5，不能显式展开。

这里必须按题面给出的规则模拟；真正的 Python `str(list(s))` 会对反斜杠等字符进行转义，不适合直接用来生成全部测试答案。

## 先学什么

先做一次朴素字符串替换，再学习“只保存影响后续转移的信息”的动态规划。关键是下标映射：旧下标 j 的字符产生新下标 `5j,5j+1,...,5j+4`。如果知道 j mod p，就知道这五个位置 mod p；因此可以按余数合并状态。

## 为什么只存 ASCII 和还不够

单引号会被双引号包裹，其他字符被单引号包裹。因此同样的 ASCII 总和，可能对应不同数量的单引号，下一轮结果也不同。

对每个余数 r 保存三个量：

- h[r]：字符个数。
- f[r]：ASCII 码之和。
- g[r]：单引号的个数。

三种量均模 10^9+7。另存真实长度对 p 的余数 len，专门确定右括号的位置；len 不能从模 10^9+7 的字符总数推导。

## 五个位置分别转移

以下新下标均对 p 取模，所有贡献都用累加，初始新数组全零。

```text
对每个 r:
    对 t=0..4: nh[5r+t] += h[r]

    nf[5r+0] += 32*h[r]                   // 空格
    nf[5r+1] += 39*h[r] - 5*g[r]          // 39变34
    nf[5r+2] += f[r]                      // 原字符
    nf[5r+3] += 39*h[r] - 5*g[r]
    nf[5r+4] += 44*h[r]                   // 逗号

    ng[5r+1] += h[r]-g[r]
    ng[5r+2] += g[r]
    ng[5r+3] += h[r]-g[r]
```

原字符为单引号时，两个包裹符号变为双引号；原字符本身仍是单引号，因此 `ng[5r+2]+=g[r]` 不能漏掉。

现在还差整个字符串的两端：第 0 位应是左括号而非空格，最后一位应是右括号而非逗号。因此：

```text
nf[0] += 91-32
newlen = 5*len mod p
nf[(newlen-1+p)%p] += 93-44
len = newlen
```

这里右侧的基础字符是 ASCII 44 的逗号。官方讲义第 17 页将两侧都描述成空格的简写不适用于右端，应以正式题面的替换规则为准。

## 例子与正确性

初始 `abc` 一轮变成 `['a', 'b', 'c']`，长度 15。若 p=16，其答案依次为 91,39,97,39,44,32,39,98,39,44,32,39,99,39,93,0，与官方样例一致。

每个字符的五个输出位置由旧下标余数唯一确定；各位置的 ASCII 贡献只依赖旧字符总和、总个数和单引号个数；两处边界修正单独处理。所以同余类内的字符可以安全合并，归纳得到每轮 h、f、g 都与完整字符串一致。

## 复杂度与坑点

初始化 O(|s|)，每轮 O(p)，总时间 O(|s|+kp)，额外空间 O(p)。p=1 时五种位置都相同，必须累加，不能赋值覆盖。初始字符串可能已含单引号，g 的初始化不能遗漏。减法统一取非负余数，乘法用 64 位。
