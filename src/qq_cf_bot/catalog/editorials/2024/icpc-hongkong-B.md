# B · Defeat the Enemies

## 先学什么

先学完全背包的有序方案计数和最短路DP。这里攻击顺序有区别，护甲被打穿时溢出的伤害完全浪费，不能把生命与护甲简单相加后做普通背包。

## 题意及记号

正式题面a[i]是生命，b[i]是护甲。每次选择1≤x≤k，对所有敌人造成x伤害，费用c[x]>0；有护甲时只扣护甲，即使溢出也不伤生命。求打败全部敌人的最低总费用，以及达到最低费用的有序攻击序列数量，模998244353。

n≤5×10^5，a、b≤m≤10^4，k≤100。官方讲义把生命/护甲符号顺序作了简化，本篇始终沿用正式题面。

## 固定总伤害S后，条件变成前缀落点

设攻击伤害的前缀和依次为0=s0<s1<...<st=S。对敌人(a,b)，第一次使前缀达到b的攻击结束后，护甲归零，设该前缀为q。以后剩余总伤害为S-q，所以敌人被打败等价于q≤S-a。

也就是某个前缀落在[b,S-a]里，不能一次跳过整个区间。

考虑一个转移p→q，q-p≤k。所有b∈(p,q]的敌人恰在这次攻击被破盾，必须同时满足

```text
q + max{ a[i] : p < b[i] ≤ q } ≤ S。
```

没有这类敌人时最大值取0。提前按护甲预处理h[b]=同护甲敌人的最大生命；其他更弱敌人不会增加约束。

## 为什么只枚举O(k)个S

令L=max(a[i]+b[i])，显然S<L无法成功。破盾的一击最多浪费k-1伤害，所以当累计伤害达到L+k-1时，所有敌人一定已死。

最优序列不可能在所有敌人已死后继续攻击，因为费用严格为正。设最优序列最后一击之前伤害为T，则T≤L+k-2，最后一击≤k，因此S≤L+2k-2。

注意计数时不能只枚举到L+k-1：某个大攻击可能恰好是最低费用的最后一击，最终伤害可以更大。

## 每个S的DP

令dp[q]为前缀伤害恰好q的最低费用，ways[q]为达到该费用的有序序列数。dp[0]=0、ways[0]=1。

对q=1..S，向后枚举x=1..min(k,q)，令p=q-x，并逐步维护max(h[p+1..q])。若上面的破盾条件满足，就用dp[p]+c[x]更新dp[q]：更小则覆盖费用和计数，相等则相加计数。

最后将所有S的dp[S]取最小，相同费用的ways[S]相加。不同S对应不同总伤害，不会重复；一个序列最后一步和前缀唯一，DP内部也不会重数。

固定S的DP可能包含“敌人已死后还攻击”的序列，但这种序列总比截断后的可行前缀更贵，不可能影响全局最低费用及计数。

例如只有生命2、护甲2，k=3、c=[2,3,3]，最低费用6，序列(2,2)、(2,3)、(3,2)、(3,3)都最优，共4种；最后一种总伤害6，大于L+k-1=5。

时间O(n+mk²+k³)，因S≤2m+2k，通常写O(n+(m+k)k²)；空间O(m+k)。费用用64位，计数单独取模。工程以真实护甲/生命状态递归枚举攻击，独立核验最低费用和序列数。尚未在线提交。
