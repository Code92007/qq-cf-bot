# H · 子序列计数：把十亿个位置压成矩阵段

## 先学什么

建议按这个顺序准备：一维子序列计数 DP → 用矩阵表示一次 DP 更新 → 矩阵快速幂 → 辗转相除 → 维护有序乘积的线段树。这里的矩阵不能交换顺序。如果你还不能解释为什么统计 `11` 时要倒序更新 DP，先写普通字符串的子序列计数，再看矩阵部分。

正式题面要求对 **998244353** 取模，原序列最多 **2000 段**，目标长度 `m≤10`，总长度 `L≤10^9`。讲义概述中的 `10^9+7` 和 `n≤1000` 与正式题面不同，本文和验证程序均以正式题面为准。

题目给出 `s'[i*k mod L]=s[i]`，不是反过来的赋值。一定先确认置换方向。

## 从普通 DP 开始

令 `f[j]` 表示已经扫描的字符中，组成目标串前 `j` 个字符的子序列数量，初始 `f[0]=1`，其余为零。读到字符 `v` 时，从大到小枚举 `j`：若 `t[j]=v`，就令 `f[j+1]+=f[j]`。

把 `f` 看作行向量，这一步等价于右乘矩阵 `A_v`：对角线全是 1，且当 `t[j]=v` 时，`A_v[j][j+1]=1`，其余位置为零。连续读到 `c` 个相同字符，等价于右乘 `A_v^c`。所有矩阵始终是 `(m+1)×(m+1)` 的上三角矩阵。

若没有洗牌，把每段的矩阵快速幂依次相乘即可。但洗牌后，相同字符会散到许多位置，不能把 `s'` 展开。

## 用逆元写出真正要计算的乘积

因为 `gcd(k,L)=1`，存在模逆元 `d=k^(-1) mod L`。因此：

```text
s'[j] = s[j*d mod L]
答案矩阵 = M[0] M[d mod L] M[2d mod L] ... M[(L-1)d mod L]
```

其中 `M[i]=A_{s[i]}`。最终答案就是这个矩阵的第 `0` 行、第 `m` 列。接下来只解决一个更一般的问题：**给定一段用游程压缩表示的矩阵序列，按模步长 d 访问时，如何保持顺序求乘积？**

## 归约一：步长太大，就反转 0 以外的部分

当 `2d>L`，令 `M'[0]=M[0]`，而 `M'[j]=M[L-j]`，也就是固定第 0 项、反转后面的序列。再把步长改成 `L-d`。

因为 `j*(L-d)≡-jd (mod L)`，有 `M'[j*(L-d) mod L]=M[j*d mod L]`。每一步访问到的矩阵都相同，乘积自然相同。实现时要把第一段拆出长度为 1 的首项，再反转剩余的段，不能把整个序列直接翻转。

## 归约二：按 d 列折叠，长度变成 d

现在 `2d≤L`。把下标按每行 `d` 个排列，最后一行可能不满：

```text
0       1       ... d-1
d       d+1     ... 2d-1
2d      2d+1    ... 3d-1
...
```

同一列中，相邻元素下标相差 `d`，所以原来的访问过程会先从上到下走完一列。令：

```text
P[j] = M[j] M[j+d] M[j+2d] ...  （只保留下标<L的项）
r = L mod d
```

从第 `j` 列的最后一项再加 `d`，取模以后，会到达第 `(j-r) mod d` 列的第一项。因此原问题等价于：**在长度 d 的矩阵序列 P 上，以步长 d-r 从第 0 项开始求乘积。**

例如 `L=8,d=3`，原下标顺序是 `0,3,6,1,4,7,2,5`；三列分别是 `(0,3,6)`、`(1,4,7)`、`(2,5)`，新步长 `3-(8 mod 3)=1`，恰好按第 0、1、2 列访问。

经过这一步，长度至少减半。结合反转归约，只需 `O(log L)` 轮。`d=1` 时会直接压成一个矩阵，可以结束。

## 关键实现：一整列的乘积也不能逐列计算

新长度 `d` 仍可能很大。考虑原矩阵的一段 `[a,b)`，这一段全部等于矩阵 `A`。第 `j` 列经过这一段的次数是：

```text
c(j) = floor((b-1-j)/d) - floor((a-1-j)/d)
```

它只有 `floor((b-a)/d)` 和再加 1 两种可能值。随着 `j` 从 `0` 走向 `d-1`，只有经过 `a mod d` 或 `b mod d` 时，这个次数才可能改变：前者加一，后者减一；余数为 0 的变化已经包含在初始值中，不再处理。

一列的乘积可以按原段的先后顺序写成 `A_1^c1 A_2^c2 ... A_p^cp`。建一棵线段树，叶子保存每段在当前列的贡献，父节点保存**左儿子矩阵乘右儿子矩阵**。先计算第 0 列的所有次数，再把全部变化余数排序。两个相邻变化位置之间，整列乘积保持不变，直接输出一段“长度 + 线段树根矩阵”；到达变化位置时，仅修改有关叶子。

对于每段，只需预计算 `A^q` 与 `A^(q+1)`，其中 `q=floor((b-a)/d)`。更新时在这两个矩阵之间切换，避免每次事件都做快速幂。同一余数上的全部更新完成后，才读取下一段的矩阵。

这就得到新序列 `P` 的游程压缩表示。原来的相邻段共享边界，所以一次折叠只会产生 `O(p)` 个变化位置；更精确地说，段数至多比原来增加 1。固定首项的反转也至多增加 1 段。因此整个归约期间，段数为 `O(n+log L)`，不会随 `L` 展开。

## 完整流程与正确性

先将输入的每个字符段换成矩阵段，求逆元 `d`。反复执行：步长大于长度一半时做固定首项的反转，否则用事件扫描和线段树折叠，再令 `(L,d)=(d,d-L mod d)`。长度为 1 时取唯一矩阵的 `[0][m]`。

子序列 DP 矩阵准确描述一次字符读取。两种归约分别逐项保持原访问顺序，或把访问中连续的一列合并成同序乘积；矩阵乘法的结合律允许合并，完全不需要交换律。每次折叠至少使长度减半，最终得到的唯一矩阵正是洗牌后按顺序扫描的总转移，所以答案正确。

令 `p=O(n+log L)`，矩阵维数为 `m+1`。使用普通矩阵乘法，一个保守总时间界为 `O(p·m³·log p·log L)`，空间为 `O(p·m²)`。快速幂的额外指数对数可按连续折叠的长度比累计进 `O(log L)`；上三角结构还可明显减少乘法常数。正式实现应使用 C++ 并复用矩阵存储，不能照搬 Python 在 2000 段极限上运行。

## 易错点与验证范围

- 普通有向赋值 `s'[i*k]=s[i]` 对应扫描时使用 `k` 的逆元。
- 行向量转移必须按扫描顺序从左向右乘；列向量写法则应整体反向约定，不能混用。
- 矩阵乘法不交换，线段树不能将左右儿子颠倒。
- 反转时固定第 0 项；折叠时先处理同一位置的全部事件。
- `a=0,j=0` 时公式含负数除法，C++ 的截断除法不等于数学下取整。可以专门初始化第 0 列：`c(0)=floor((b-1)/d)+1`（a=0），其余 a>0 时使用非负数公式。
- 使用正式模数 998244353。不能依据讲义概述改成另一个模数。

专项验证程序实际实现了非交换矩阵折叠和线段树：与 1200 组小规模任意上三角矩阵的模下标直接乘积比较，再对 2000 组真实洗牌序列逐字符统计子序列。另检查全部官方样例和长度约 `10^9` 的常值序列，其答案应为组合数 `C(L,m)`。这些检查确认了归约与实现边界，尚未在线评测或测试 2000 段极限性能。
